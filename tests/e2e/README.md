# End-to-End Tests — fixed QA suite

Playwright tests for apps generated by BUNYAN AI.

**Owner:** Sara (QA Tester Agent)

One fixed suite of **8 checks**, parameterised by `requirements.json` and, when given, `architecture.json`. No tests are generated per app.
Element names follow the `data-testid` rules in the Architect contract (`0.3.0-proposal`, §5).

> **Status:** the 8 check ids and `pass_rate` are agreed with Jood (T1, T2). The report format is `0.2.0-proposal`.
> See [`contract/TEST_REPORT.md`](contract/TEST_REPORT.md) §6 for the open points.

## The 8 checks

| id | What it checks |
|---|---|
| `create_item` | Add a record through the form; it appears in the list and the count grows by one |
| `list_items` | Three records are listed, each row showing every column in `crud.read.list_fields`; numbers follow `display_format` |
| `edit_item` | Edit opens a pre-filled form; after saving, the list shows the new value and not the old one |
| `delete_item` | The confirmation text names the record; cancelling keeps it; confirming removes only that record |
| `persist_after_refresh` | A saved record is still listed after reload (localStorage) |
| `reject_incomplete_input` | Saving with required fields empty adds nothing, before or after reload |
| `empty_state` | With no records the empty-state message is shown; it hides after the first record |
| `error_message_visible` | Saving with required fields empty shows a non-empty error next to each of them |

The ids are the ones used by the dashboard (`frontend/`). These 8 checks do **not** cover every acceptance criterion (for example search, filters, `no-results`, min/max length and date rules are not in the 8).

### Messages (rule M1)

With `architecture.json`, texts listed in `verbatim_messages` (quoted in the acceptance criteria) must match **exactly**: the save and delete buttons, the delete confirmation, the empty state and a required-field error. Every other message is only checked to be **visible**. Details: [`contract/TEST_REPORT.md`](contract/TEST_REPORT.md) §3.

### Empty required fields

The two empty-input checks leave empty every required field **without** a default, including a select that starts empty (`empty_option`). A required field **with** a default is pre-filled, so it is never left empty (same rule as the Business Analyst, AC-2).

## Setup (once)

```bash
cd tests/e2e
npm install
npx playwright install chromium
```

## Run

```bash
cd tests/e2e
npx playwright test
```

By default this tests the **harness fixture** (`fixtures/task-manager/`) against the `task_manager_en` samples (the Architect sample is used when it exists).
The fixture is hand-written so the suite can be developed before the Developer agent exists. It renders whatever `architecture.json` the suite is given, so it can stand in for any sample. **Passing on the fixture does not prove a generated app works.** The report says so in `inputs.is_harness_fixture` and `warnings`.

Test a generated app (Git Bash):

```bash
REQUIREMENTS=path/to/requirements.json ARCHITECTURE=path/to/architecture.json APP_DIR=path/to/generated/app npx playwright test
```

After a repair, re-test with the attempt number (1 or 2):

```bash
QA_ATTEMPT=1 APP_DIR=path/to/generated/app npx playwright test
```

Simulated defects on the fixture, to check that the suite catches them:

| `APP_PATH` | Expected to fail |
|---|---|
| `/?bug=no-persist` | `persist_after_refresh` |
| `/?bug=wrong-text` | the checks that compare verbatim texts |
| `/?bug=no-format` | `list_items` (when a list column has `display_format`) |
| `/?bug=no-empty-option` | `reject_incomplete_input`, `error_message_visible` (when a required select has no default) |

```bash
APP_PATH="/?bug=no-persist" npx playwright test
```

| Variable | Default |
|---|---|
| `REQUIREMENTS` | `backend/agents/business_analyst/samples/outputs/task_manager_en.requirements.json` |
| `ARCHITECTURE` | `backend/agents/architect/samples/outputs/task_manager_en.architecture.json` if it exists, otherwise none |
| `APP_DIR` | `tests/e2e/fixtures/task-manager` |
| `APP_PATH` | `/` |
| `QA_ATTEMPT` | `0` |
| `REPORT_PATH` | `reports/test_report.json` |
| `PORT` | `4317` |

## Output

- `reports/test_report.json` — results of the real run (format: [`contract/TEST_REPORT.md`](contract/TEST_REPORT.md)).
- `reports/artifacts/` — screenshot and trace of each failed check (open a trace with `npx playwright show-trace <file>`).

`reports/` is not committed.

## Limits (MVP)

- Exactly one entity, no `reference` fields (open decision D9). Other documents are refused and every check is reported as `not_run`.
- Only `ready_for_review` documents are tested.
- Without `architecture.json`, messages are only checked to be visible; verbatim texts, `confirm-delete-text` and `display_format` are not checked (the report adds a warning).
- Chromium only.

## Files

| Path | Purpose |
|---|---|
| `specs/crud.spec.js` | The 8 checks |
| `lib/checks.js` | Fixed list of check ids and their acceptance-criteria categories |
| `lib/requirements.js` | Reads `requirements.json` and `architecture.json`, builds valid sample values, verbatim texts and number formats |
| `lib/report.js` | Playwright reporter that writes `test_report.json` |
| `lib/serve.js` | Local static server for the app under test (also serves `architecture.json` to the fixture) |
| `fixtures/task-manager/` | Harness fixture app driven by `architecture.json` (not a generated app) |
| `contract/TEST_REPORT.md` | `test_report.json` format, message rules and open points |
