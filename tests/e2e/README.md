# End-to-End Tests — fixed QA suite

Playwright tests for apps generated by BUNYAN AI.

**Owner:** Sara (QA Tester Agent)

One fixed suite of **8 checks**, parameterised by `requirements.json`. No tests are generated per app.
Element names follow the `data-testid` rules in the Architect contract (`0.2.0-proposal`, §5, branch `feature/naifah-architect`).

> **Status: proposal.** The list of checks, the `data-testid` names and the `test_report.json` format are not agreed yet.
> See [`contract/TEST_REPORT.md`](contract/TEST_REPORT.md) §5 for the open points.

## The 8 checks

| id | What it checks |
|---|---|
| `create_item` | Add a record through the form; it appears in the list and the count grows by one |
| `list_items` | Three records are listed, each row showing every column in `crud.read.list_fields` |
| `edit_item` | Edit opens a pre-filled form; after saving, the list shows the new value and not the old one |
| `delete_item` | Cancelling the delete keeps the record; confirming removes only that record |
| `persist_after_refresh` | A saved record is still listed after reload (localStorage) |
| `reject_incomplete_input` | Saving with required fields empty adds nothing, before or after reload |
| `empty_state` | With no records the empty-state message is shown; it hides after the first record |
| `error_message_visible` | Saving with required fields empty shows a non-empty error next to each of them |

The ids are the ones already used in `frontend/src/mocks/placeholders.js`. These 8 checks do **not** cover every acceptance criterion (for example search, filters, min/max length and date rules are not in the 8).

## Setup (once)

```bash
cd tests/e2e
npm install
npx playwright install chromium
```

## Run

```bash
cd tests/e2e
npx playwright test
```

By default this tests the **harness fixture** (`fixtures/task-manager/`) against Ghala's `task_manager_en` sample.
The fixture is hand-written so the suite can be developed before the Developer agent exists. **Passing on the fixture does not prove a generated app works.** The report says so in `inputs.is_harness_fixture` and `warnings`.

Test a generated app (Git Bash):

```bash
REQUIREMENTS=path/to/requirements.json APP_DIR=path/to/generated/app npx playwright test
```

After a repair, re-test with the attempt number (1 or 2):

```bash
QA_ATTEMPT=1 APP_DIR=path/to/generated/app npx playwright test
```

Simulate a storage defect on the fixture (expect `persist_after_refresh` to fail):

```bash
APP_PATH="/?bug=no-persist" npx playwright test
```

| Variable | Default |
|---|---|
| `REQUIREMENTS` | `backend/agents/business_analyst/samples/outputs/task_manager_en.requirements.json` |
| `APP_DIR` | `tests/e2e/fixtures/task-manager` |
| `APP_PATH` | `/` |
| `QA_ATTEMPT` | `0` |
| `REPORT_PATH` | `reports/test_report.json` |
| `PORT` | `4317` |

## Output

- `reports/test_report.json` — results of the real run (format: [`contract/TEST_REPORT.md`](contract/TEST_REPORT.md)).
- `reports/artifacts/` — screenshot and trace of each failed check (open a trace with `npx playwright show-trace <file>`).

`reports/` is not committed.

## Limits (MVP)

- Exactly one entity, no `reference` fields (open decision D9). Other documents are refused and every check is reported as `not_run`.
- Only `ready_for_review` documents are tested.
- Required selects with a default (e.g. Task `priority`, `status`) cannot be left empty, so the two empty-input checks skip them and the report adds a warning.
- Chromium only.
